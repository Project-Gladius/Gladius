# 전투 데이터 JSON 항목 설명

이 폴더의 JSON 3개는 통합 시뮬레이터가 함께 사용하는 초기 전투 데이터입니다. 기존 계산 설명은 2026-09-24 기준이며, 보스 상태·패턴 및 축복 정의는 **2026-10-18**에 갱신했습니다. 보스 JSON과 현재 HTML의 호환성은 2-4절을 참고하세요. 표의 현재값은 이후 밸런스 편집에 따라 달라질 수 있습니다.

| 파일                                   | 담고 있는 데이터                                                      |
| -------------------------------------- | --------------------------------------------------------------------- |
| [abilities.json](abilities.json)       | 공통 전투 규칙, 캐릭터별 HP·공격·방어, 시작 상태, 분석 기본 설정      |
| [bosses.json](bosses.json)             | 보스 상태, 구역별 물리·마법 내성, 상태를 묶은 패턴                    |
| [enhancements.json](enhancements.json) | 강화 1단계당 증가량, 초기 강화 단계, 치명타 확률 상한, 축복 정의 목록 |

실제 게임에서도 사용할 수 있도록 나눈 데이터입니다. **현재 Unreal 게임에 이 JSON이 자동 연동되어 있다는 뜻은 아닙니다.** 게임에서 사용하려면 동일한 규격과 계산 순서를 읽는 로더가 필요합니다.

## 읽는 방법과 공통 항목

- `characters[]`, `actions[]`처럼 `[]`가 붙은 표기는 배열의 각 항목을 뜻합니다. 실제 JSON 키에는 `[]`가 없습니다.
- 비율은 **1 = 100%**로 저장합니다. `0.25`는 25%, `0.5`는 50%입니다. 치명타 **추가** 피해 50%는 최종 피해 **1.5배**를 뜻합니다.
- `left` / `center` / `right`는 플레이어 화면 기준 **좌 / 중 / 우**입니다.
- `physical` / `magical`은 **물리 / 마법**입니다.
- `true` / `false`는 **켜기 / 끄기**입니다. `null`은 항목에 따라 별도 의미가 있으며, 피버 상한에서는 **무제한**을 뜻합니다.
- `id`는 다른 데이터가 참조하는 고유 식별자, `name`은 화면에 표시할 이름입니다. 이름이 같아도 ID가 다르면 별개 데이터입니다.

파일별 메타데이터입니다.

| 항목            | 뜻                      | 현재값 / 사용법                                                           |
| --------------- | ----------------------- | ------------------------------------------------------------------------- |
| `schemaVersion` | JSON 구조의 버전        | 모두 `1`. 확장 필드의 실행 지원 여부도 확인해야 합니다.        |
| `kind`          | 파일 종류 식별자        | 능력치: `gladius-abilities`, 보스: `gladius-boss-patterns`, 강화: `gladius-enhancements`. |
| `revision`      | 데이터 내용의 개정 번호 | 능력치 `1`, 보스 `2`, 강화 `2`.                                      |

## 1. abilities.json — 초기 능력치와 전투 규칙

### 1-1. 출처

| 항목         | 뜻                                                                                           | 현재값                             |
| ------------ | -------------------------------------------------------------------------------------------- | ---------------------------------- |
| `sourceSave` | 초기값을 가져온 기존 세이브 파일명. 출처 기록용이며 이 파일을 자동으로 다시 읽지는 않습니다. | `V1_2026-09-09T06-34-31-643Z.json` |

### 1-2. rules — 모든 캐릭터가 공유하는 전투 규칙

| 항목                     | 뜻                                       | 현재값 / 적용 예                                                                                                      |
| ------------------------ | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `attackFeverGain`        | 공격 행동 후 증가하는 피버               | `5`. 현재 공격 피해를 계산한 뒤 피버 +5.                                                                              |
| `defenseFeverGain`       | 방어 행동 후 증가하는 피버               | `5`. 실제로 피격했는지와 관계없이 방어 행동으로 +5.                                                                   |
| `feverDamageCoefficient` | 피버를 공격력에 더할 때 곱하는 계수      | `1`. 기본 공격력 10, 피버 5이면 내성·치명타 적용 전 피해는 15.                                                        |
| `evadeThreshold`         | 피버 감소가 발동하는 연속 회피 기준 횟수 | `2`. 2회 연속 회피부터 감소. 공격·방어는 연속 회피를 끊습니다.                                                        |
| `evadeReduction`         | 발동 시 현재 피버에서 감소시키는 비율    | `1` = 100% 감소, 즉 피버 0. `0.5`라면 절반 감소. **보존율이 아닙니다.**                                               |
| `evadeRepeat`            | 긴 연속 회피에서 감소를 반복하는 방식    | `everyAfter`: N회째부터 매번. `eachN`: 연속 N회마다. 현재 `everyAfter`.                                               |
| `feverRounding`          | 회피 비율 감소 후 피버의 소수 처리       | `floor`: 내림, `round`: 반올림, `none`: 소수 유지. 현재 `floor`. 현재 구현의 소수 유지는 소수점 8자리까지 정리합니다. |
| `feverCap`               | 피버 갱신 후 적용할 상한                 | `null` = 무제한. 숫자이면 그 값을 넘지 못합니다. 피버 하한은 0.                                                       |
| `allowStayEvade`         | 현재 위치를 목적지로 한 회피의 허용 여부 | `true` = 허용. `false` = 제외. 위치 모드와 AI 전투에 적용되며, 확률 모드는 목적지를 구분하지 않습니다.                |
| `attackDamageRounding`   | 실제 플레이어 공격 피해의 정수 처리      | `roundHalfUp` 고정. 0.5 이상 올리는 반올림.                                                                           |
| `defenseDamageRounding`  | 방어 비율을 적용한 피격 피해의 정수 처리 | `ceil` 고정. 소수가 있으면 올림.                                                                                      |
| `turnOrder`              | 한 턴의 처리 순서를 저장한 배열          | `move` → `playerAttack` → `bossAttack` → `feverAndDeath` 고정.                                                        |
| `resistanceMultipliers`  | 보스의 내성 상태별 피해 배율을 담은 객체 | 아래 표 참고.                                                                                                         |

`turnOrder`의 의미는 **회피 이동 → 플레이어 공격 → 보스 공격 → 피버·사망 갱신**입니다. 공격한 턴에 사망해도 그 턴의 플레이어 피해는 기록합니다. 반올림 방식과 처리 순서는 현재 고정 계약이므로 다른 값으로 바꾸면 검증 오류가 납니다.

`resistanceMultipliers`의 하위 항목:

| 항목         | 뜻                      | 현재값 |
| ------------ | ----------------------- | -----: |
| `enduring`   | 보스가 해당 속성을 버팀 |  0.5배 |
| `normal`     | 보통                    |    1배 |
| `vulnerable` | 보스가 해당 속성에 취약 |  1.5배 |

예: 피버 8, `evadeThreshold=2`, `evadeReduction=0.5`일 때 4번 연속 회피하면, `everyAfter`는 **8 → 4 → 2 → 1**, `eachN`은 **8 → 4 → 4 → 2**가 됩니다.

### 1-3. initial — 전투 시작 상태

| 항목          | 뜻                                               | 현재값      |
| ------------- | ------------------------------------------------ | ----------- |
| `fever`       | 시작 피버                                        | `0`         |
| `zone`        | 기본 시작 위치                                   | `left` = 좌 |
| `evadeStreak` | 시작 시 이미 누적된 것으로 취급할 연속 회피 횟수 | `0`         |

시작 HP는 별도 `initial.hp`가 아니라 **선택 캐릭터의 `baseHp` + 체력 강화분**으로 계산합니다. 각 실험에 시작 상태를 따로 지정하면 해당 실험의 설정이 적용됩니다.

### 1-4. characters[] — 캐릭터별 기본 능력치

| 항목                 | 뜻                                                             | 현재값 / 사용법                                                                                                   |
| -------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `id`                 | 캐릭터 고유 ID                                                 | `gladius`, `sera`                                                                                                 |
| `name`               | 캐릭터 표시 이름                                               | 글라디우스, 세라                                                                                                  |
| `baseHp`             | 강화 전 기본 최대 HP                                           | 두 캐릭터 모두 `7`                                                                                                |
| `defenseDamageRatio` | **방어 시 피해 비율**. 방어할 때 원래 피해 중 실제로 받는 비율 | 두 캐릭터 모두 `0.5` = 50%. 피해 2라면 1을 받습니다. **피해 감소율과 구분**하세요. 값이 작을수록 방어가 강합니다. |
| `skills`             | 해당 캐릭터의 공격 2개를 담은 배열                             | 첫 번째 원소가 공격 1, 두 번째 원소가 공격 2.                                                                     |

`characters[].skills[]`의 하위 항목:

| 항목         | 뜻                                                     | 현재 공격 1 / 공격 2                               |
| ------------ | ------------------------------------------------------ | -------------------------------------------------- |
| `id`         | 해당 캐릭터 안에서 공격을 구분하는 ID                  | `attack_1` / `attack_2`                            |
| `name`       | 공격 표시 이름                                         | 기본 베기 / 집중 타격                              |
| `baseDamage` | 강화·피버·내성·치명타 적용 전 기본 공격력              | `10` / `7`                                         |
| `attribute`  | 이 공격의 속성. 보스의 같은 속성 내성을 조회할 때 사용 | `physical` / `physical`                            |
| `critChance` | 강화 전 치명타 확률                                    | `0` / `0.25` = 0% / 25%                            |
| `critBonus`  | 치명타 발생 시 더해지는 추가 피해 비율                 | `0` / `0.5` = +0% / +50%. 공격 2의 치명타는 1.5배. |

현재는 원본 세이브에 캐릭터 구분이 없어 **글라디우스와 세라 모두 같은 능력치와 물리 공격으로 시작**합니다. 각각 별도로 수정할 수 있으며, 세라라는 이름만으로 마법 속성이 자동 적용되지는 않습니다.

### 1-5. simulationDefaults — 시뮬레이터 전용 기본 설정

게임 캐릭터의 능력치가 아니라 분석 화면의 설정입니다.

| 항목                | 뜻                                            | 현재값                                                                  |
| ------------------- | --------------------------------------------- | ----------------------------------------------------------------------- |
| `initialLines`      | 최초 탐색에서 표시할 추천 행동 라인 수        | `10`                                                                    |
| `additionalLines`   | 행동을 수정한 뒤 추가로 탐색할 대안 수        | `3`                                                                     |
| `uniqueDamage`      | 같은 기대 피해의 라인을 묶어 대표만 표시할지  | `true`. 피해를 소수점 8자리 기준으로 구분합니다.                        |
| `probabilityByTurn` | 확률 모드에서 사용할 턴별 피격·내성 설정 배열 | 현재 10개. 배열 첫 항목은 1턴. 위치 모드의 공격 구역 판정과 별개입니다. |

`probabilityByTurn[]`의 하위 항목:

| 항목       | 뜻                                                              | 현재값                                |
| ---------- | --------------------------------------------------------------- | ------------------------------------- |
| `pa`       | 플레이어가 공격했을 때 **보스에게 피격될 확률**                 | `0.5` = 50%                           |
| `pd`       | 방어했을 때 보스에게 피격될 확률                                | `0.5` = 50%                           |
| `pe`       | 회피했을 때 보스에게 피격될 확률                                | `0.15` = 15%. 회피 성공률이 아닙니다. |
| `damage`   | 피격 시 받는 원래 피해. 방어하면 캐릭터의 방어 비율을 추가 적용 | `2`                                   |
| `physical` | 이 턴의 보스 물리 내성                                          | `normal`                              |
| `magical`  | 이 턴의 보스 마법 내성                                          | `normal`                              |

## 2. bosses.json — 보스 행동과 패턴 (2026-10-21 갱신)

버전 2의 상태·패턴 내용을 보존하고 기존 버전 1 구조로 되돌렸습니다. 트루돈의 행동 13개와 패턴 22개를 유지합니다. `states`, `sequence`, `turns`, `totalDamage`, `telegraphText`, `simulation`은 저장하지 않습니다.

### 2-1. 기본 정보

`schemaVersion`은 `1`, `kind`는 `gladius-boss-patterns`, `revision`은 1턴 패턴을 추가한 개정인 `2`입니다. `name`은 트루돈, `maxHp`는 100입니다. `bossId`, `zoneIds`는 사용하지 않습니다.

### 2-2. actions[] — 한 턴의 행동

한 행동은 한 턴의 상태입니다. 공격뿐 아니라 `Defense`, `Defenseless`도 포함합니다.

| 필드 | 의미 |
|---|---|
| `id` | 기존 상태 ID를 그대로 유지한 행동 ID. |
| `name` | 표시 이름. 별도 이름이 없던 상태는 ID를 사용. |
| `hitCount` | 한 턴 안의 타격 횟수. 현재 모두 1. |
| `damageByZone` | `left`, `center`, `right`의 1타당 피해. 기존 총 피해를 타격 구역마다 그대로 기록하고 나머지는 0. 구역 수로 나누지 않음. |
| `attributeByZone` | 구역별 보스 공격 속성. 기존 변환 방식대로 모두 `physical`. |
| `resistanceByZone` | 구역별 보스 `physical`·`magical` 내성. 물리 값은 이전 데이터를 유지하고 마법은 모두 `normal`. |
| `telegraph.text` | 기존 `test:` 예고 문구를 그대로 이동. |
| `telegraph.motionId`, `attackMotionId` | 기존 형식 호환용 빈 문자열. 연출은 추후 행동 ID를 통해 별도 스크립트로 연결. |

내성 값은 `enduring`(견딤), `normal`(보통), `vulnerable`(취약)입니다. 현재 능력치 JSON에서 각각 0.5, 1, 1.5배이며, 플레이어가 보스에게 주는 피해에 적용합니다.

`AllStrike`와 세 `StrongStrike`의 타격 구역 피해는 2, 나머지 공격은 1, 비공격 상태는 모든 구역 0입니다.

**Fury의 데이터 보존 확장:** Fury에는 `target: {"mode":"randomOne","zones":["left","center","right"]}`를 남겼습니다. `damageByZone`의 각 1은 해당 구역이 선택되었을 때의 피해입니다. 의도된 실행은 세 구역 중 하나만 선택하는 것입니다. 현재 게임의 버전 1 로더는 이 추가 필드를 읽지 않아 그대로 실행하면 세 구역 모두 피해 1로 처리합니다. 시뮬레이터는 무작위 단일 구역 적용을 지원하며, 게임 코드의 후속 대응은 필요합니다. 버전 번호 복귀만으로 이 동작이 구현된 것은 아닙니다.

### 2-3. patterns[] — 여러 행동의 순서

| 필드 | 의미 |
|---|---|
| `id` | `pattern_01`부터 `pattern_22`까지 부여한 고유 ID. 선택 설정에서 참조. |
| `name` | 기존 패턴 이름 그대로 유지. |
| `steps` | 기존 `sequence`를 그대로 옮긴 행동 ID 배열. 한 원소가 한 턴. |

소요 턴 수는 `steps.length`로 계산하며 별도의 `turns`는 저장하지 않습니다. 기존 16개 패턴은 2~3턴이며, 좌·중·우·좌중·중우·좌우의 1턴 패턴 6개를 추가해 총 22개입니다. 행동 ID와 패턴 순서는 변경하지 않았습니다.

```json
{
  "id": "pattern_01",
  "name": "좌, 중, 우",
  "steps": ["SingleStrikeLeft", "SingleStrikeCenter", "SingleStrikeRight"]
}
```

### 2-4. 실행 설정

- `encounter`: `turns: 10`, `patternFit: "remainingTurns"`.
- `selection`: `mode: "weightedRandom"`, `allowImmediateRepeat: true`. `pool`에 22개 패턴 ID와 각각 가중치 1을 기록합니다.
- `preset`: `mode: "random"`, `seed: 20261018`. 모드 전환용 `customPatterns`는 첫 패턴 ID, `directActions`는 첫 패턴의 행동 순서를 보관합니다.
- 게임에서 `custom`·`direct` 모드로 전환할 때는 해당 목록의 총 턴 수와 `encounter.turns`를 일치시켜야 합니다.

현재 게임은 랜덤 모드에서 양의 가중치인 1턴 패턴을 요구합니다. 추가한 6개 패턴은 각각 가중치 1이며 연속 선택도 허용하므로, 남은 1~10턴 모두에서 선택 가능한 후보가 존재합니다. 기존 2~3턴 패턴과 함께 총 10턴을 채웁니다.

2026-10-21 시뮬레이터 갱신: 통합 HTML은 현재 JSON 3종을 내장하며 버전 1 행동·다중 턴 패턴·Fury의 무작위 단일 구역 타격·분리된 내성을 지원합니다. 일반 HTML도 현재 보스 JSON을 불러와 턴으로 펼칠 수 있습니다. 일반 HTML의 능력치·강화 JSON 개별 불러오기는 지원하지 않습니다. 축복 정의는 통합 HTML에서 보존하지만 효과 계산은 아직 연결하지 않았습니다.

## 3. enhancements.json — 강화 수치와 축복 정의

### 3-1. perLevel — 강화 1단계당 증가량

| 항목         | 뜻                                           | 현재값                                                                        |
| ------------ | -------------------------------------------- | ----------------------------------------------------------------------------- |
| `hp`         | 체력 강화 1단계당 최대 HP 증가               | `1` = HP +1                                                                   |
| `damage`     | 공격 강화 1단계당 각 공격의 기본 피해 증가   | `1` = 공격 1·2 모두 +1                                                        |
| `critChance` | 치명타 확률 강화 1단계당 확률 증가           | `0.05` = **+5%p**. 25%에서 30%로 증가.                                        |
| `critBonus`  | 치명타 피해 강화 1단계당 추가 피해 비율 증가 | `0.1` = **+10%p**. 추가 피해 50%에서 60%로, 최종 배율 1.5배에서 1.6배로 증가. |

### 3-2. initialLevels — 기본 강화 단계

| 항목         | 뜻                         | 현재값 |
| ------------ | -------------------------- | -----: |
| `hp`         | 시작 체력 강화 단계        |      0 |
| `damage`     | 시작 공격 강화 단계        |      0 |
| `critChance` | 시작 치명타 확률 강화 단계 |      0 |
| `critBonus`  | 시작 치명타 피해 강화 단계 |      0 |

각 값은 서로 독립적인 단계 수입니다. 실제 유저의 강화 보유 기록을 저장한 목록은 아닙니다. 실험에서 강화 단계를 별도로 지정하면 해당 실험값을 사용합니다.

### 3-3. 최상위 상한

| 항목            | 뜻                                              | 현재값                         |
| --------------- | ----------------------------------------------- | ------------------------------ |
| `critChanceCap` | 기본 확률과 강화분을 합친 최종 치명타 확률 상한 | `1` = 100%. 두 공격 모두 적용. |

강화 계산식:

```text
최대 HP = characters[].baseHp + initialLevels.hp × perLevel.hp
공격력 = skills[].baseDamage + initialLevels.damage × perLevel.damage
치명타 확률 = min(critChanceCap, skills[].critChance + initialLevels.critChance × perLevel.critChance)
치명타 추가 피해 = skills[].critBonus + initialLevels.critBonus × perLevel.critBonus
```

기본 치명타 확률이 0인 공격 1도 치명타 확률 강화를 적용하면 치명타가 발생할 수 있습니다.

### 3-4. blessings[] — 축복 정의 (2026-10-18 추가)

`enhancements.json`의 `blessings` 배열에 축복을 저장합니다. 기존 강화 수치 필드와 별도로 관리하며, 축복마다 아래 네 필드를 갖습니다.

| JSON 필드     | 자료형 | 의미                                                                                                |
| ------------- | ------ | --------------------------------------------------------------------------------------------------- |
| `id`          | int    | 축복의 고유 정수 ID. 목록 안에서 중복되지 않아야 합니다.                                            |
| `title`       | string | 축복 제목. 접미사 없이 저장하며 UI에서 `{title}의 축복`으로 표시합니다. 예: `회복` → `회복의 축복`. |
| `relatedStat` | string | 축복이 관련된 능력치. 아래 식별자 중 하나를 사용합니다.                                             |
| `displayText` | string | 축복 설명으로 표시할 텍스트. `{변수명}`은 수치 치환 자리입니다.                                     |

관련 능력치의 허용 식별자:

| `relatedStat` | 능력치             |
| ------------- | ------------------ |
| `currentHp`   | 현재 체력          |
| `maxHp`       | 최대 체력          |
| `baseAttack`  | 기본 공격력        |
| `feverAttack` | FeverAttack 공격력 |
| `critChance`  | 치명타 확률        |
| `critDamage`  | 치명타 데미지      |

예시 축복:

| ID  | 저장 제목 | UI 제목       | 관련 능력치  | 표시 텍스트                                    |
| --- | --------- | ------------- | ------------ | ---------------------------------------------- |
| 1   | 회복      | 회복의 축복   | `currentHp`  | 체력을 `{HPGen}`만큼 회복함                    |
| 2   | 힘        | 힘의 축복     | `baseAttack` | 기본 공격력을 `{AtkInc}`만큼 증가시킴          |
| 3   | 민첩      | 민첩의 축복   | `critChance` | 치명타 확률을 `{CritInc}` %p만큼 증가시킴      |
| 4   | 예리함    | 예리함의 축복 | `critDamage` | 치명타 데미지를 `{CritDmgInc}` %p만큼 증가시킴 |

```json
{
  "id": 1,
  "title": "회복",
  "relatedStat": "currentHp",
  "displayText": "체력을 {HPGen}만큼 회복함"
}
```

`HPGen`, `AtkInc`, `CritInc`, `CritDmgInc`의 실제 수치는 아직 지정하지 않았습니다. 추후 축복 시스템에서 값을 제공하고 표시 텍스트의 해당 자리를 치환합니다. `displayText`는 표시용 문자열이며 계산식을 실행하거나 파싱하는 용도가 아닙니다.

`CritInc`와 `CritDmgInc`는 **퍼센트포인트(%p)** 단위입니다. 예를 들어 확률 20%에 `CritInc = 5`를 적용하면 25%입니다. 0~1 비율을 쓰는 게임 데이터에 반영할 때는 100으로 나눕니다. 이 규칙은 표시용 치환 변수에 대한 것이며, 기존 `perLevel` 필드의 단위는 바꾸지 않습니다.

현재 최대 체력·FeverAttack 공격력은 허용 능력치로 정의하며, 해당 축복 예시는 아직 추가하지 않았습니다. 이 절은 데이터와 표시 형식 정의이며, 실제 축복 적용·턴별 초기화는 추후 축복 시스템에서 연결합니다.

## 4. 함께 적용되는 계산 예

현재 공격 2를 강화 없이 사용하고, 피버가 5, 물리 내성이 보통이라고 가정합니다.

```text
일반 피해 = 반올림((7 + 5 × 1) × 1) = 12
치명타 피해 = 반올림((7 + 5 × 1) × 1 × (1 + 0.5)) = 18
기대 피해 = 12 × (1 - 0.25) + 18 × 0.25 = 13.5
공격 후 피버 = 5 + 5 = 10
```

실제 공격은 12 또는 18의 정수 피해입니다. **기대 피해나 반복 실험 평균이 소수인 것은 반올림 누락이 아닙니다.** 일반·치명타 피해를 각각 반올림한 뒤 평균을 냅니다.

이전 공격 형식의 계산 예로, 보스 피해 3, `hitCount=2`, 방어 시 피해 비율 50%라면 (현재 행동은 모두 `hitCount=1`):

```text
방어 피격 피해 = 올림(3 × 0.5) × 2 = 2 × 2 = 4
방어하지 않은 피격 피해 = 3 × 2 = 6
```

방어는 **1타당 비율을 적용해 올림한 다음 타격 횟수를 곱합니다.**

## 5. 편집 시 참고

- 숫자는 따옴표 없이, 비율은 소수로 입력합니다. JSON에는 주석을 넣지 않습니다.
- 행동 ID를 바꾸면 `patterns[].steps`, `preset.directActions`도 수정합니다. 패턴 ID를 바꾸면 `selection.pool[].patternId`, `preset.customPatterns`도 수정합니다.
- 구역별 객체는 `left`, `center`, `right`를 모두 유지하고, 내성 객체에는 `physical`, `magical`을 모두 지정합니다.
- 행동·패턴은 각각 최대 100개, 패턴의 `steps`는 1~4개입니다. 현재 `hitCount`는 모두 1입니다.
- 저장한 JSON을 사용하려면 통합 HTML에서 **Data 폴더 연결** 또는 **JSON 3개 불러오기**를 사용합니다. HTML을 더블클릭하기만 하면 빌드 당시 포함된 데이터 복사본으로 시작합니다.
- 화면의 **JSON 직접 편집 → 검증·적용**은 메모리에 적용합니다. 파일에도 반영하려면 저장 버튼을 사용합니다.

시뮬레이터 실행 안내는 [시뮬레이터 사용 방법](../시뮬레이터%20사용%20방법.md), 개발·계산 규칙은 [통합 시뮬레이터 안내](../Simulator/README.md)를 참고하세요.
