# 전투 기본 시스템

> [!info] 문서 기준
> [노션 원문 — 전투 기본 시스템](https://app.notion.com/p/397f2cb114f980748f22c0a6540c77f2)을 Obsidian용으로 정리한 문서다. 원문의 수치·식별자·요구사항을 보존하고, 미완성 문장과 해석이 필요한 부분은 별도로 표시했다. 관련 분석 문서는 [[게임 수치 분석 시뮬레이션 기획서]]다. 이 문서는 전투 원문을 옮긴 것으로, 분석 문서의 실험 범위를 변경하지 않는다.

## 1. 기획서 개요

- 프로그래머의 기본 전투 시스템 구현을 위한 기획서다.
- 기획회의 결정에 따라 방송 시청자인 플레이어가 알기 힘든 사항은 의도적으로 배제한다. 문서에 없는 플레이어 관련 별도 시스템이나 기믹의 추가는 지양한다.
- 신전에서의 능력치 강화는 별도 기획서에서 다룬다.

## 2. 작업 방침

### 전체 작업 흐름

원문의 ‘전체적인 작업 흐름’은 이미지로 첨부되어 있다. [노션 원문](https://app.notion.com/p/397f2cb114f980748f22c0a6540c77f2)에서 확인한다.

> [!note] 이미지 범위
> 첨부 이미지는 이 파일에 복사하거나 내용으로 전사하지 않았다. 아래 내용은 원문 텍스트를 정리한 것이다.

### 구현과 데이터 저장

- 핵심 시스템의 뼈대와 코드 구조를 고려한다.
- API 연동을 고려한다. 이재국 담당의 [유튜브 유저 데이터 저장 관련 문서](https://app.notion.com/p/3a2f2cb114f980d089bbe14add7f1097)에 구현된 기능과 UID 기준으로 연동한다.
- 전시 이벤트 운영을 위해 스트리밍·게임 종료 이후에도 유저 데이터를 보존한다.
- 일정한 형식의 파일로 저장하고, 다른 컴퓨터에서 불러와 연속 실행할 수 있어야 한다.

## 3. 전장

- 전투가 이루어지는 그래픽 환경이다.
- 3D perspective view를 사용한다. Isometric이 아닌 원근법을 적용한다.
- 화면 전방에 보스 구역, 카메라 쪽에 플레이어 구역을 배치한다.
- 플레이어 구역은 좌·중·우로 3등분한다.

### 3.1 최대 참여 인원과 대기열

- 비주얼과 트래픽 문제를 고려하여 `MaxPlayers = 30`으로 제한한다.
- 전투 명령어로 전장에 참여한다.
- 상시 표시 UI에 `현재 참여 인원 / MaxPlayers` 형태로 서버 혼잡도를 표시한다. 상세 비주얼은 추후 기획한다.
- 정원 초과 시 게임에 포함하지 않고 대기열에 등록한다.

YouTube API 댓글 안내:

> 현재 정원이 초과되어 게임 참여가 불가능합니다. `대기열 인원 수` 명 대기 중.

`!대기열` 입력 시 인원 수를 안내한다.

| 상태 | 댓글 안내 |
|---|---|
| 대기열 없음 | 현재 대기열에 유저가 없습니다. 댓글창에 명령어를 입력해 전투에 참여하세요! |
| 대기열 있음 | 현재 정원이 초과되어 게임 참여가 불가능합니다. `대기열 인원 수` 명 대기 중. |

대기열 진입 처리는 다음과 같다.

1. 대기열 첫 번째부터 순회한다.
2. 해당 유저가 현재 방송을 시청 중인지 조회한다.
3. 시청 중이면 아래 댓글을 출력한다.
4. 가장 가까운 ‘플레이어 행동 선택’ 턴에 해당 유저를 진입시킨다.

> 대기열에 여유 공간이 있습니다. 잠시 후 대기열 첫 번째 유저인 `참여할 유저 닉네임` 이 자동으로 전투에 참가됩니다!

> [!question] 구현 확인 사항
> 방송 시청 여부의 조회 수단, 미시청자의 대기열 처리 방식은 원문에서 구체화되지 않았다. 위 문구는 원문 표현을 보존했다.

## 4. 유저 위치와 UI

원활한 UI 표시를 위해 경기장에 보이지 않는 유저 위치인 ‘스팟’을 지정한다.

### 4.1 머리 위 UI

유저 머리 위에 `UI 표시 위치`를 지정하고 UI를 배치한다.

| 표시 모드 | 동작 |
|---|---|
| `None` | UI 숨김 |
| `FullUI` | 모든 UI 표시 |
| `NameOnly` | 플레이어 이름만 표시 |

| 설정 | 형식 | 동작 |
|---|---|---|
| `UIPerspective` | bool | 켜면 카메라 거리에 따라 크기 변화, 끄면 크기 유지 |
| `UIRenderMinDistance` | float | 기준 거리 성분이 이 값보다 작으면 숨김 |
| `UIRenderMaxDistance` | float | 기준 거리 성분이 이 값보다 크면 불투명도 100% |

거리 기준은 원문에서 ‘카메라와의 거리의 lookat 벡터 성분’으로 표현한다. 최소·최대 거리 사이에서는 불투명도를 선형 증가시킨다. 자세한 표시는 [UI 관련 문서](https://app.notion.com/p/397f2cb114f980e0961fd444fe07f979)에서 지정한다.

### 4.2 비행동 구간의 스팟 배치

보스 행동 예고부터 대기 턴까지는 이전 턴의 좌·중·우 구역 안에서 정해진 스팟에 위치한다.

- 턴 시작 시 일제히 움직인다.
- 가장 가까운 스팟을 우선한다.
- 이전 턴에 선택한 구역을 벗어나지 않는다.
- 구역 안에서 최대한 고르고 서로 떨어져 배치한다.
- 대체로 글라디우스를 세라보다 보스에 가깝게 배치한다.
- 세라는 앞에 공간이 있어도 보스와 일정 거리를 유지한다.

피해야 할 배치·움직임:

- 같은 직업의 플레이어끼리 서로 가로지르는 움직임.
- 글라디우스가 가까운 세라보다 보스에서 먼 스팟에 서는 배치.
- 좌측 또는 우측 스팟에 지나치게 많은 플레이어가 몰리는 배치.
- 인원이 매우 적어도 서로 붙어 있는 배치.
- 구역의 스팟 수보다 많은 인원이 몰리는 상황.

스팟 초과 시 예비 스팟, 옆 구역 이동, 최대 인원 조정, 인원별 스팟 배치를 회의·테스트로 검토한다. **최초 개발은 고정 스팟·고정 인원으로 진행한다.**

### 4.3 행동 구간의 이동

| 캐릭터 | 공격·방어 | 회피 |
|---|---|---|
| 글라디우스 | 해당 구역 안에서 최대한 보스에게 붙어 모션 수행 | 명령어의 구역으로 회피 모션을 취하며 이동 |
| 세라 | 현재 자리에서 모션 수행 | 명령어의 구역으로 회피 모션을 취하며 이동 |

## 5. 게임과 턴

게임은 `Turns = 10`개 턴으로 구성된다. 플레이어는 매 턴 행동을 선택하여 보스로부터 생존하는 것을 목표로 한다.

### 5.1 보스 행동 예고

- 보스가 모션과 텍스트로 다음 행동을 보여준다.
- 이 시간에 입력한 선택도 유효하다.
- 플레이어는 `Idle` 모션을 유지하고, 행동 관련 표시는 선택 턴 시작 이후 표시한다.

### 5.2 플레이어 행동 선택

- 보스 예고 모션 종료 후 `PlayerSelectCountdown = 90`초 카운트다운을 시작한다.
- 보스는 해당 모션의 종료 자세를 취하고 텍스트는 유지한다.
- 플레이어는 모션과 텍스트로 다음 행동을 유추한다.
- 선택은 여러 번 변경 가능하며 **가장 최근 입력**을 이번 턴 행동으로 사용한다.
- 대기 턴 종료 전까지 준비 모션을 취하고, 행동 턴에 일괄 실행하여 중복 행동을 막는다.
- 준비 모션 표시가 어려우면 아이콘으로 대체한다.
- 모델링 전시를 위해 `CameraSwitchTime = 30`초마다 카메라 위치와 각도를 변경한다. 시점은 Milestone 2의 별도 기획에서 결정한다.

### 5.3 대기

- 카운트다운 이후 서버 딜레이를 심리적으로 보정하는 구간이다.
- 선택 카운트다운과 다른 별도 타이머로 대기 시간을 표시한다.
- **대기 종료 시점까지 입력된 행동을 반영한다.**

### 5.4 유저 행동 및 보스 모션

1. 플레이어 이동: UI를 `NameOnly`로 바꾸고, 위치 변경 규칙에 따라 이동 모션을 수행한다.
2. 플레이어 공격 및 보스 피격 모션: 함께 싸우는 형태로 연출한다.
3. 무작위 순서로 `AttackTerm` 간격마다 `AttackCount`명의 플레이어가 공격한다.
4. 공격 시 보스 머리 위에 피해량을 출력한다. 치명타·속성 내성 표현은 UI 기획에서 별도 정의한다.
5. 세라는 투사체 도착 시간을 고려한 `SeraAttackDelay`를 사용한다.

> [!question] 원문 미완성 부분
> 세라 딜레이 설명은 ‘딜레이 이후’에서 끝나 있다. 지연 이후 피해 판정·숫자 표시 중 무엇을 처리하는지는 미정이다. 보스 실제 공격 판정의 정확한 시점과 대기 구간 길이도 명시되어 있지 않다.

## 6. 보스 패턴

보스는 미리 지정한 패턴을 무작위 선택하여 행동한다. 한 패턴이 끝나면 다른 패턴을 무작위 선택한다. 패턴은 여러 행동의 조합이다.

| 보스 행동 속성 | 내용 |
|---|---|
| 주는 피해량 | 플레이어에게 주는 피해 |
| 물리 내성치 | 물리 공격에 적용 |
| 마법 내성치 | 마법 공격에 적용 |
| 모션 | 해당 행동의 모션 |
| 알림 텍스트 | 플레이어에게 보여줄 텍스트 |
| 피격 범위 | 좌, 중, 우, 좌/중, 중/우, 좌/우, 전범위, 랜덤, 없음 |

## 8. 행동 효과

### 8.1 공격

- 최종 피해량만큼 보스에게 피해를 준다.
- 가한 피해를 누적 피해량에 더한다.
- 피격되면 받는 피해량만큼 현재 체력을 감소시킨다.
- 피버를 `FeverIncrement = 1`만큼 증가시킨다.

### 8.2 방어

- 피격되면 받는 피해량을 `DefenceDivisor = 2`로 나누고 **올림**한 만큼 체력을 감소시킨다.
- 피버를 `FeverIncrement = 1`만큼 증가시킨다.

$$
\text{방어 시 체력 손실}=\left\lceil\frac{\text{받는 피해량}}{2}\right\rceil
$$

### 8.3 회피

- 명령어로 지정한 구역으로 이동한다.
- 피격되면 받는 피해량만큼 현재 체력을 감소시킨다.
- 원문의 수정사항에 따라 `FeverLossTurn` 연속 회피 시 피버에 `FeverLoss`를 곱하며, 피버는 정수이므로 **내림**한다.

$$
F'=\left\lfloor F\times\text{FeverLoss}\right\rfloor,\qquad 0\le\text{FeverLoss}\le1
$$

> [!note] 수정 이력과 입력 용어
> 원문에 남아 있는 `FeverDecrement = 2` 고정 감소는 수정 전 규칙으로 구분하며, 수정된 연속 회피 규칙과 동시에 적용하지 않는다. 위 식은 ‘FeverLoss 배’라는 원문 표현을 남는 비율로 해석한 것이다. 분석 문서의 ‘N회 연속 회피 시 M% 감소’와 연결하면 **N=FeverLossTurn, M=100×(1−FeverLoss)**다.

원문은 기준 횟수 도달 뒤 매 회피에 적용하는지, N회마다 적용하는지 명시하지 않는다. 이 부분은 분석 문서의 반복 적용 설정과 별도로 구현 확정이 필요하다.

## 9. 공격과 피해

직업군별 공격은 2개이며 각 공격은 기본 피해량과 공격 속성을 가진다. 공격 속성은 `Physical` 또는 `Magical`이다.

보스는 행동별로 서로 다른 물리·마법 내성을 가진다.

| 내성 | 배율 |
|---|---:|
| `Enduring` | 0.5 |
| `Normal` | 1.0 |
| `Vulnerable` | 1.5 |

$$
\text{최종 피해량}=(\text{기본 피해량}+\text{추가 피해량}+F)\times\text{공격 속성에 대한 보스 내성치}\times(1+\text{치명타 시 추가 피해율})
$$

치명타가 아니면 마지막 배율은 1이다. 원문의 치명타 피해량 40%는 식에 따라 치명타 시 1.4배로 해석된다. 추가 피해량과 강화 피해량의 연결 방식, 최종 피해의 소수 처리는 원문에 명시되지 않았다.

## 10. 게임 오버와 재개

- 플레이어 체력이 0이 되면 게임 오버 처리한다.
- 게임 오버 후 `GameOverTurns = 3`턴 동안 플레이 불가이며 이후 부활한다.
- 부활 직전 방송 시청 여부를 검사한다.
- 부활 시 상점 이용이 가능하다.
- 부활 시 ‘강화’ 능력치의 `GameOverLoss = 50`%를 잃는다.
- 플레이 불가 상태에서 슈퍼챗을 받으면 능력치를 잃지 않고 즉시 부활한다.
- 중도 로그아웃 시 현재 스탯을 보존하고 캐릭터를 제외하며 서버 현재 인원을 1 줄인다.
- 중도 로그인 시 로그아웃 당시 스탯을 보존한 상태로 전투에 진입한다. 서버가 만원이면 로그인할 수 없다.

> [!question] 원문 미완성 부분
> 부활 시청 검사 설명은 ‘방송을 시청 중이 아니라면 플레이 가능한’에서 끝나 있다. 미시청자의 처리, 부활 체력과 피버, 3턴 산정 시작점, 능력치 손실의 정수 처리, 슈퍼챗 대상 식별·조건은 원문만으로 확정할 수 없다.

## 11. 주요 설정값 모음

| 설정 | 원문 값 | 용도 |
|---|---|---|
| `MaxPlayers` | 30 | 최대 참여 인원 |
| `Turns` | 10 | 게임 턴 수 |
| `PlayerSelectCountdown` | 90초 | 행동 선택 시간 |
| `CameraSwitchTime` | 30초 | 카메라 전환 간격 |
| `AttackTerm` | 미정 | 공격 연출 간격 |
| `AttackCount` | 미정 | 동시에 공격하는 인원 |
| `SeraAttackDelay` | 미정 | 세라 투사체 지연 |
| `FeverIncrement` | 1 | 공격·방어 피버 증가 |
| `DefenceDivisor` | 2 | 방어 피해 나눗수, 결과 올림 |
| `FeverLossTurn` | 미정 | 연속 회피 발동 횟수 |
| `FeverLoss` | 0~1, 구체값 미정 | 회피 발동 후 피버 보존 배율, 결과 내림 |
| `GameOverTurns` | 3 | 게임 오버 후 대기 턴 |
| `GameOverLoss` | 50% | 부활 시 해당 능력치 손실률 |

> [!note] 문서 간 적용 범위
> 이 파일에는 전투 원문의 플레이어 데이터와 부활 규칙을 보존했다. [[게임 수치 분석 시뮬레이션 기획서]]는 별도 문서이며, 이번 전사에서 수정하지 않았다. 연결된 API·UI 문서의 본문과 작업 흐름 이미지 내용은 이 문서에 포함하지 않았다.
