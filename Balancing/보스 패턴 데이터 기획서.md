# 보스 패턴 데이터 기획서

> [!abstract] 목적
> 길이가 서로 다른 1~4턴 공격 패턴을 정의하고, 패턴이 끝날 때마다 가중 랜덤으로 다음 패턴을 선택한다. 인게임과 시뮬레이터는 동일한 JSON 파일을 읽어 사용한다.

관련 문서: [[전투 기본 시스템]], [[게임 수치 분석 시뮬레이션 기획서]]. 예제 데이터: [boss_patterns.sample.json](boss_patterns.sample.json).

> [!info] 확정 범위와 예시
> 1~4턴 패턴 및 가중 랜덤 선택은 사용자 요청 사항이다. 아래 실행 세부 규칙은 초기 구현을 위한 제안이며, JSON의 보스·패턴 이름, 피해량, 가중치, 예고 문구 및 모션 ID는 실험용 예시다. 실제 모션 리소스가 연결되어 있다는 뜻은 아니다.

## 1. 파일 구조

보스별 JSON 파일 하나에 행동 정의, 패턴, 선택 규칙을 함께 둔다. UTF-8 인코딩을 사용하며 JSON 안에는 주석을 넣지 않는다. 기획 설명은 이 문서나 데이터의 description 필드에 작성한다.

| 구분 | 필드 | 의미 |
|---|---|---|
| 파일 | schemaVersion | 파서가 지원해야 하는 형식 버전 |
| 파일 | bossId, name | 보스 고유 ID와 표시 이름 |
| 파일 | revision | 내용 변경 시 증가시키는 데이터 버전 |
| 파일 | description | 기획용 설명 |
| 행동 | actions | 한 턴 단위 행동 목록 |
| 패턴 | patterns | 행동을 순서대로 묶은 1~4턴 패턴 목록 |
| 선택 | selection | 가중 랜덤 및 연속 재선택 규칙 |
| 전투 구간 | encounter | 총 턴 수와 남은 턴에 따른 후보 제한 |

ID는 영문 소문자·숫자·밑줄을 사용하고 파일 안에서 각 종류별로 유일하게 유지한다. 표시 이름을 바꾸더라도 ID는 유지한다. 인게임은 모션 ID를 실제 리소스에 연결하며 시뮬레이터는 연출을 생략할 수 있다.

## 2. 행동 정의

**행동 하나는 한 턴이다.** 같은 행동을 여러 패턴에서 참조할 수 있다. 특정 패턴에서 수치가 달라야 한다면 별도 행동 ID를 정의한다. 첫 버전은 패턴 안에서 행동 수치를 덮어쓰는 기능을 두지 않는다.

| 필드 | 형식 | 설명 |
|---|---|---|
| id, name | 문자열 | 고유 ID와 기획용 이름 |
| damage | 0 이상의 정수 | 방어 감소를 적용하기 전 플레이어 피해 |
| target.mode | fixed | 첫 버전은 명시적인 구역 지정만 사용 |
| target.zones | 구역 배열 | 실제 피격 구역 |
| resistanceByZone | 구역별 객체 | 플레이어 위치별 물리·마법 내성 |
| telegraph.text | 문자열 | 행동 선택 전에 표시할 예고 문구 |
| telegraph.motionId | 문자열 | 예고 모션 리소스 연결 ID |
| attackMotionId | 문자열 | 실행 모션 리소스 연결 ID |

### 구역과 피격

- 구역은 플레이어 화면 기준 left·center·right다. 카메라 전환에 따라 논리 구역을 다시 정의하지 않는다.
- 복수 구역은 배열로 표현한다. 좌/중은 `["left", "center"]`, 전범위는 세 구역 전체, 공격 없음은 빈 배열이다.
- 구역은 중복해서 기입할 수 없다.
- 회피 이동 후 위치가 공격 구역에 포함되면 해당 플레이어가 피격된다.
- 공격 범위는 같은 턴의 모든 플레이어에게 공유한다.

### 속성 내성

left·center·right 각각에 physical·magical을 모두 기입한다. 내성은 enduring·normal·vulnerable 중 하나다. 이를 통해 오른쪽 공격 중 왼쪽에서 물리 공격하면 더 큰 피해를 주는 구조를 표현한다.

내성 배율은 공통 전투 규칙에서 관리한다. 현재 기본 기획서의 대응값은 enduring=0.5, normal=1.0, vulnerable=1.5다. 각 행동마다 배율 숫자를 중복 저장하지 않는다.

내성은 **그 행동이 예고된 턴의 플레이어 공격**에 적용하며, 이동 후 플레이어 구역을 사용한다. 보스 공격 범위와 속성 내성은 별도 항목이다.

## 3. 패턴 정의

| 필드 | 설명 |
|---|---|
| id, name | 패턴 고유 ID와 표시 이름 |
| description | 패턴의 기획 의도 |
| steps | 실행 순서대로 나열한 행동 ID 배열, 길이 1~4 |

패턴 길이는 steps의 길이로 계산한다. 별도 duration 값을 두어 길이가 서로 불일치하는 상황을 피한다. 같은 행동 ID를 한 패턴 안에서 여러 번 참조하는 것은 허용한다.

예를 들어 `right_swing → center_slam → left_swing`은 3턴 패턴이다. 실행 중에는 가중치를 다시 뽑지 않으며, 순서대로 끝까지 진행한다.

## 4. 가중 랜덤 선택

selection.mode는 weightedRandom이다. pool에는 patternId와 weight를 저장한다. 패턴 정의와 선택 가중치를 분리하여 행동 순서를 바꾸지 않고 출현 빈도를 조절할 수 있게 한다.

먼저 남은 턴 수 이하 길이의 패턴만 남기고, 가중치 0 및 연속 재선택 제한에 해당하는 패턴을 제외한다. 이렇게 얻은 선택 가능한 패턴 집합을 E라 하면:

$$
P(i)=\frac{w_i}{\sum_{j\in E}w_j}
$$

- 가중치는 0 이상의 유한한 숫자다. 0은 선택 비활성화를 뜻한다.
- 합계가 100일 필요는 없다.
- 최소 하나의 선택 가능한 패턴은 양의 가중치를 가져야 한다.
- 예제는 allowImmediateRepeat=true다. 직전 패턴을 다시 선택할 수 있다.
- false로 설정하면 직전 패턴을 후보에서 빼고 남은 가중치를 다시 정규화한다. 이 모드에서는 서로 다른 양의 가중치 패턴이 최소 2개 필요하며, 남은 턴 제한과 함께 적용해도 모든 도달 가능한 상태에서 후보가 있어야 한다. 후보가 없을 때 임의로 제한을 무시하지 않고 설정 오류로 처리한다.
- pool의 배열 순서를 누적 가중치 구간 순서로 사용한다. 총합 W에 대해 0 이상 W 미만의 난수를 뽑아 구간을 선택한다.

### 길이가 다른 패턴의 출현율

가중치는 **턴마다의 출현 확률이 아니라 패턴을 새로 고를 때의 확률**이다. 긴 패턴은 한 번 뽑히면 더 많은 턴을 차지한다.

| 예제 패턴 | 길이 | 가중치 | 선택 시 확률 |
|---|---:|---:|---:|
| single_center | 1 | 40 | 40% |
| right_center | 2 | 30 | 30% |
| side_combo | 3 | 20 | 20% |
| full_combo | 4 | 10 | 10% |

연속 재선택 허용, 고정 가중치, 충분히 긴 실행에서는 평균 패턴 길이가 2턴이고 각 패턴의 턴 점유율은 약 20%·30%·30%·20%다.

$$
\text{턴 점유율}_i\approx\frac{w_iL_i}{\sum_jw_jL_j}
$$

이 근사는 10턴처럼 짧은 실험의 정확한 결과가 아니며, 연속 재선택 제한이 있으면 그대로 적용하지 않는다. 출력에는 패턴 선택 횟수와 실제 점유 턴 수를 둘 다 기록한다.

## 5. 실행 순서와 10턴 경계

1. 완료한 턴이 10이면 전투 구간을 종료한다. 그렇지 않고 활성 패턴이 없으면 남은 턴에 들어가는 후보 중 가중 랜덤으로 패턴 하나를 고른다.
2. 현재 step의 예고 모션과 문구를 제공한다.
3. 플레이어 행동을 선택하고 회피 이동을 반영한다.
4. 해당 행동의 위치별 내성으로 플레이어 공격 피해를 계산한다.
5. 해당 행동의 범위와 피해량으로 보스 공격을 판정한다.
6. 공통 전투 규칙에 따라 체력·피버 등을 갱신한다.
7. 다음 턴에 다음 step으로 이동한다. 마지막 step이 끝났을 때만 다음 패턴을 고른다.

플레이어 공격과 보스 피격의 구체적인 판정 순서는 공통 전투 규칙으로 관리하며 양쪽 실행기가 같아야 한다. 위 순서는 현재 시뮬레이션 초안의 처리 가정을 따른다.

> [!important] 확정 규칙: 정확히 10턴에 패턴과 함께 종료
> 남은 턴 안에 들어가는 패턴만 추첨한다. 선택된 패턴은 끝까지 실행하며, 총 10턴이 완료되는 시점에 마지막 패턴도 끝난다. 패턴 중간 절단, 10턴 초과 실행, 다음 구간으로의 패턴 승계는 하지 않는다.

JSON의 encounter.turns=10, encounter.patternFit=remainingTurns로 이 규칙을 명시한다. 남은 턴 R은 10에서 완료한 턴 수를 뺀 값이다. 패턴을 새로 고를 때 steps 길이가 R 이하인 패턴만 후보에 포함한다.

예제 가중치에서 후보와 확률은 다음과 같다. 연속 재선택 허용 기준이다.

| 남은 턴 | 후보 길이 | 길이별 선택 확률 |
|---|---|---|
| 4 이상 | 1·2·3·4 | 40%·30%·20%·10% |
| 3 | 1·2·3 | 4/9·3/9·2/9 |
| 2 | 1·2 | 4/7·3/7 |
| 1 | 1 | 100% |
| 0 | 없음 | 추첨 없이 종료 |

예를 들어 8턴을 완료했다면 남은 2턴에 들어가는 1·2턴 패턴만 추첨한다. 1턴 패턴을 뽑았다면 마지막 턴에도 1턴 패턴을 추첨하고, 2턴 패턴을 뽑았다면 그대로 마무리한다.

예제는 양의 가중치인 1턴 패턴을 포함하고 연속 재선택을 허용하므로 항상 정확히 10턴을 채울 수 있다. 다른 설정에서는 모든 도달 가능한 ‘남은 턴·직전 패턴’ 상태를 확인하여 막히는 경우가 있으면 로딩 오류로 처리한다. 빈 턴을 임의로 추가하거나 남은 턴보다 긴 패턴을 대신 고르지 않는다.

종료 직전에는 짧은 패턴의 선택 비율이 높아진다. 따라서 전체 10턴 실험의 출현율을 원래 가중치 비율과 동일하다고 해석하지 않고, 남은 턴별 후보·정규화 확률·실제 선택 횟수를 기록한다.

## 6. 데이터 분리와 재현

| 데이터 | 저장 위치 |
|---|---|
| 보스 행동·패턴·선택 가중치 | 이 보스 JSON |
| 방어 나눗수, 피버 증가, 회피 N·M, 내성 배율 | 별도 공통 전투 규칙 |
| 체력, 공격 1·2, 속성, 치명타 | 플레이어·공격 데이터 |
| 숙련도, 판독 오류, 행동 정책, 실행 횟수 | 시뮬레이션 설정 |
| 현재 패턴 ID, step, 난수 상태 | 실행 상태 또는 세이브 |

Pa·Pd·Pe는 이 파일에 넣지 않는다. 실제 패턴 모델에서는 공격 구역과 플레이어 행동으로 피격을 판정한다. 확률 근사 분석의 입력값은 별도로 관리한다.

완전 정보 시뮬레이터는 전체 패턴을 읽을 수 있으나, 숙련도별 정책에는 허용된 예고·기억만 제공한다. 실제 다음 행동을 초보 정책에 자동으로 알려주지 않는다.

재현 기록에는 bossId·revision·파일 내용 해시, 공통 전투 규칙 버전, 난수 시드, 선택된 패턴과 실행 step을 포함한다. 같은 시드만으로 서로 다른 언어의 난수 결과가 같아지는 것은 아니므로 공통 난수 알고리즘을 정하거나 실제 선택 로그를 재생한다. 보스 선택용 난수 흐름은 치명타·연출용 난수와 분리한다.

## 7. 로딩과 검증

실행 전에 전체 파일을 읽고 검사한 뒤 사용한다. 첫 구현은 JSON 직접 편집으로 시작하고, 이후 표 형태 편집기가 같은 JSON을 저장하도록 확장할 수 있다.

- schemaVersion 지원 여부와 필수 필드·자료형 확인.
- 행동 ID와 패턴 ID의 중복 금지.
- 모든 steps 참조가 실제 행동을 가리키는지 확인.
- 패턴 길이 1~4 검사.
- 구역·속성 내성 이름과 구역 중복 검사.
- 피해량과 가중치 범위 검사.
- pool의 patternId 존재 여부와 중복 검사.
- 양의 가중치 후보 수 및 재선택 제한 조건 검사.
- 남은 턴별 후보 제한과 모든 도달 가능한 상태의 정확한 10턴 완료 가능 여부 검사.
- 인게임에서는 모션 ID가 실제 리소스와 연결되는지 추가 검사.

오류는 파일명과 항목 위치를 표시하고 실행 전에 수정한다. 모르는 구역이나 누락 내성을 정상값으로 조용히 대체하지 않는다. JSON Schema는 후속 구현 시 형식 검증에 사용하고, ID 참조 등 항목 간 관계는 별도 검사한다.

## 8. 예제와 후속 구현 범위

예제 JSON은 4개의 단일 행동과 각각 1·2·3·4턴 길이인 4개 패턴을 제공한다. 모든 예제 공격은 한 구역만 때리며 물리 취약 위치를 일부 배치했다. 이는 방어를 강제하기 위한 전범위 공격이 아니라 이동·피버 관리 실험의 시작점이다.

- [ ] 인게임·시뮬레이터 파서 및 공통 규칙 연결.
- [ ] JSON Schema 파일 및 편집기 검증 연결.
- [ ] 모션 ID와 실제 게임 리소스 연결.
- [ ] 가중 선택·패턴 지속·10턴 경계 검증.
- [ ] 패턴별 선택 빈도와 턴 점유율 출력.
