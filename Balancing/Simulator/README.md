# Gladius 통합 밸런스 시뮬레이터

`Balancing/Gladius 통합 시뮬레이터.html`을 Chrome 또는 Edge로 엽니다. 인터넷과 설치가 필요하지 않습니다.

## 공통 데이터

`Balancing/Data`의 다음 3개 JSON이 공통 원본입니다.

| 파일 | 내용 |
|---|---|
| abilities.json | 캐릭터별 체력·공격·방어 시 피해 비율, 공통 전투 규칙, 기본 시작 조건 |
| bosses.json | 보스 공격, 여러 공격을 묶은 패턴, 가중치, 보스 설정 방식과 실행 순서 |
| enhancements.json | 강화 단계당 증가량과 기본 강화 단계 |

HTML을 더블클릭하면 빌드 시 포함한 **동일 JSON 3개의 복사본**으로 시작합니다. 브라우저는 인접한 로컬 파일을 자동으로 읽을 수 없으므로 **Data 폴더 연결**을 눌러 `Balancing/Data`를 선택하면 디스크의 최신 파일을 사용합니다. 연결한 후 각 저장 버튼은 해당 JSON을 직접 수정합니다. 파일 선택기 사용이 불가능한 브라우저에서는 **JSON 3개 불러오기**와 다운로드 저장을 사용하세요.

로컬 웹 서버에서 열면 `Data/*.json`을 자동으로 읽습니다. 외부 JSON 읽기에 실패하면 내장 복사본 사용 사실을 화면에 표시합니다. JSON 세트는 3개 모두 읽고 검증한 다음 한 번에 적용합니다. 로딩 실패 시 기존 데이터는 유지됩니다.

`JSON 직접 편집`에서 내용을 바꾼 뒤 `검증·적용`으로 메모리에 반영하거나 `검증·적용·파일 저장`으로 파일에 저장합니다. 파일에 저장하지 않은 변경은 창을 닫으면 사라집니다. 개정 번호는 JSON의 `revision`으로 관리할 수 있습니다.

## 초기값

파일 수정 날짜가 같으므로 저장 파일명 시각 기준 최신인 `Saves/V1_2026-09-09T06-34-31-643Z.json`을 사용했습니다.

- HP 7, 피버 0, 시작 위치 좌, 연속 회피 0.
- 공격 1: 물리 10, 치명타 0%.
- 공격 2: 물리 7, 치명타 25%, 치명타 추가 피해 50%.
- 공격·방어 피버 +5, 2연속 회피부터 매회 피버 100% 감소, 피버 소수 내림.
- 글라디우스와 세라 모두 같은 세이브 수치로 시작하며 각각 편집할 수 있습니다. 캐릭터가 구분되지 않은 저장 파일이므로 세라의 속성을 임의로 마법으로 바꾸지 않았습니다.
- 캐릭터별 방어 시 피해 비율 50% = 기존 피해 ÷2. 비율 적용 후 받는 피해는 올림합니다.
- 최신 세이브의 10턴 보스 공격·내성과 순서를 그대로 이전했습니다. 처음에는 `공격 직접 지정` 모드입니다.
- 강화 증가량은 전투 데이터 레퍼런스의 HP +1, 피해 +1, 치명타 확률 +5%p, 추가 피해 +10%p입니다. 기본 강화는 모두 0단계입니다.

## 보스 편집

- **패턴 랜덤 설정:** 남은 턴 이하 길이의 패턴만 후보에 넣고 가중치로 추첨합니다. 한 패턴이 끝난 뒤 다음 패턴을 선택합니다. 남은 턴과 직전 패턴 제한 때문에 막히는 경우 실행 전 오류로 알립니다.
- **패턴 사용자 지정:** 저장된 패턴을 선택해 순서대로 배치합니다. 총 1~10턴이며 패턴을 중간에 자르지 않습니다.
- **공격 직접 지정:** 기존 첫 번째 시뮬레이터처럼 1~10턴의 개별 공격을 직접 편집합니다.

저장된 패턴 목록에는 이름만 표시됩니다. 이름을 펼쳐 공격을 1~4개 묶고 순서·가중치를 편집할 수 있습니다. 공격 사전의 항목을 여러 패턴에서 참조할 수 있습니다. 한 공격을 편집하면 그 ID를 참조한 모든 위치에 적용됩니다. 특정 턴만 다르게 만들려면 `이 턴용 공격 복제`를 사용하세요. 같은 표시 이름이어도 ID가 다르면 별개 공격입니다.

현재 선택하지 않은 실행 방식의 순서는 보관합니다. 비활성 방식의 턴 합계나 랜덤 완주 가능성은 해당 방식으로 전환했을 때 검사합니다. 참조 ID와 자료형은 항상 검사합니다.

## 두 실험

**최적 행동 탐색:** 선택 캐릭터의 생존 가능한 고정 행동 순서를 비교합니다. 위치 모드의 추천은 정확 탐색입니다. 행동 셀을 수정하면 그 턴까지 고정한 추가 라인이 생성됩니다. 전체 생존·딜 분포는 허용된 모든 고정 라인을 동일하게 세며, 현재 위치 회피 ON이면 턴당 6개, OFF이면 5개입니다. 확률 모드는 Pa/Pd/Pe를 실험값으로 따로 입력합니다.

**AI 전투 실험:** 참가자별 캐릭터·판독 확률·HP 임계치·체력 및 사망 비용을 사용합니다. 예측 깊이 기본은 10턴이며 변경 가능합니다. 랜덤 모드는 관측한 현재 공격으로 패턴 후보를 갱신합니다. 사용자 지정·직접 지정 모드는 예정된 미래 행동을 아는 비교 실험입니다. 이 두 정보 조건을 동일한 숙련도 결과로 해석하지 마세요. 자동 전투 재생, 반복 사망 확률, HP×판독 확률 비교, 기본 행동 정책 비교, CSV 내보내기를 제공합니다.

실험은 시작 당시 공통 데이터의 복사본을 사용합니다. 한 실험을 실행·취소하거나 결과를 편집해도 다른 실험의 HP·피버·결과는 변경되지 않습니다. 공통 데이터를 수정하면 기존 결과에 이전 설정으로 계산한 결과임을 표시합니다. 다시 실행하면 최신 공통값이 적용됩니다.

AI 실험은 구간 사이 HP·피버·사망 상태를 유지하고 반복 실험마다 초기화합니다. 두 분석 모두 보스 HP를 소모하지 않고 누적 피해를 측정합니다. `maxHp`는 실제 게임용 데이터이며 분석의 종료 조건이 아닙니다.

## 고정 계산 계약

1. 회피 이동.
2. 이동한 구역의 내성, 피버 갱신 전 값으로 플레이어 공격.
3. 보스 공격과 플레이어 HP 차감.
4. 피버·연속 회피·사망 갱신.

공격 피해: `max(0, floor((공격력 + 피버 × 계수) × 내성 × 치명타 배율 + 0.5))`.
치명타 배율은 일반 1, 치명타 `1 + critBonus`입니다. 확률 기대 피해는 일반·치명타 피해를 각각 반올림한 후 가중 평균합니다. 따라서 실제 타격은 정수이고 기대값·평균은 소수가 될 수 있습니다. 사망하는 턴에 가한 공격 피해도 기록합니다.

방어 피해: `ceil(구역의 1타당 피해 × 캐릭터의 defenseDamageRatio) × hitCount`.
공격·방어 이외의 피격은 `구역의 1타당 피해 × hitCount`입니다.

## JSON 규격 요약

세 파일은 UTF-8, `schemaVersion: 1`, 양의 정수 `revision`을 사용합니다. ID는 소문자·숫자·밑줄이며 표시 이름과 구분합니다. 비율은 0~1로 저장하고 UI에서 %로 표시합니다.

- `abilities.kind = gladius-abilities`: `characters[].skills[]`의 `baseDamage`, `attribute`, `critChance`, `critBonus`; `characters[].baseHp`, `defenseDamageRatio`; `rules`의 피버·내성·이동 규칙. `attackDamageRounding`, `defenseDamageRounding`, `turnOrder`는 고정 계약입니다. `simulationDefaults`의 탐색 개수와 확률 근사는 게임에서 무시합니다.
- `bosses.kind = gladius-boss-patterns`: `actions[]`은 `damageByZone`, `attributeByZone`, `resistanceByZone`에 left/center/right를 모두 지정합니다. `hitCount`는 한 턴 내 동일 타격 횟수입니다. `patterns[].steps`는 1~4개 공격 ID입니다. `selection.pool`은 `{patternId, weight}` 목록입니다. `preset`은 `mode`, `seed`, `customPatterns`, `directActions`를 보관합니다. `encounter.turns`는 랜덤 구간 길이이며 `patternFit=remainingTurns`입니다. 예고 문구·모션 ID는 게임 연출용으로 저장합니다.
- `enhancements.kind = gladius-enhancements`: `perLevel`과 `initialLevels`의 `hp`, `damage`, `critChance`, `critBonus`; `critChanceCap`. 각 공격의 치명타에 강화분이 더해지므로 공격 1도 강화 후 치명타가 발생할 수 있습니다.

이 JSON은 Unreal 로더가 구현해야 할 공통 데이터 규격입니다. 이번 변경은 HTML 통합과 JSON 제공이며 Unreal 게임 코드·레벨을 수정하지 않았습니다. 기존 보스 예제 JSON의 단일 `damage`·`target.zones` 구조와는 구역별 피해 표현이 다르므로 그대로 호환되는 것으로 취급하지 마세요.

난수는 Mulberry32이며 패턴 추첨과 AI·치명타 난수 흐름을 분리합니다. Unreal에서 같은 시드의 재현이 필요하면 동일 32비트 연산 또는 선택 로그 재생을 구현해야 합니다.

## 개발·검증

`Balancing/Simulator`의 `engine.js`, `ui.js`, `style.css`, `shell.html`이 소스입니다. 두 실험과 Worker, 자동 테스트는 동일한 전투 엔진 코드를 사용합니다.

```text
node Balancing/Simulator/build.cjs
node Balancing/Simulator/tests.cjs
```

빌드는 `Balancing/Data`의 3개 JSON을 읽어 HTML의 오프라인 시작 복사본을 갱신합니다. 빌드에 외부 패키지는 필요하지 않습니다. 런타임은 HTML 한 파일이며 JavaScript 소스 파일을 별도로 불러오지 않습니다.
